# Feeledu · 조교 출퇴근 및 급여 관리

> **실사용 학원 조교 출퇴근·급여 관리 웹앱 (Cloudflare Workers + SQLite + Android TWA)**
>
> - **운영 환경**: 학원 데스크 태블릿(`/kiosk`) 및 PC 관리자(`/admin`), 무중단 클라우드 운영
> - **담당 범위**: 서비스 배포·권한 분리·세션 정책 설계, CI/CD 자동 검증·배포, 백업·복구 무결성 검증 및 운영 문서화
> - **핵심 확인 문서**: [운영·백업 안내](docs/OPERATIONS.md) · [보안 점검](docs/SECURITY_REVIEW.md) · [CI 자동 검증](.github/workflows/ci.yml)

**무료 클라우드 운영:** [관리자 화면](https://feeledu-attendance.feeledu-pj-managing.workers.dev/admin) · [태블릿 출퇴근](https://feeledu-attendance.feeledu-pj-managing.workers.dev/kiosk). PC가 꺼져 있어도 같은 서버를 사용합니다. 사용자가 새 시작을 선택해 기존 로컬 계정·직원·급여는 이전하지 않았습니다. [Cloudflare 운영·백업 안내](deploy/CLOUDFLARE.md)를 참고하세요.

**Android APK 설치:** [GitHub Releases](https://github.com/dpqksr5501/Feeledu_PJ_Managing/releases/latest)에서 `feeledu-attendance.apk`를 내려받아 설치합니다. [APK 직접 다운로드](https://github.com/dpqksr5501/Feeledu_PJ_Managing/releases/latest/download/feeledu-attendance.apk). Google Android Browser Helper의 검증된 Trusted Web Activity로 같은 서버를 실행합니다. 브라우저 설치 메뉴를 찾을 필요가 없습니다. 자세한 빌드·서명·릴리즈 절차는 [android/README.md](android/README.md)를 참고하세요.

**지속 배포:** 작업 브랜치에서 수정·검증한 뒤 `main`에 반영하면 GitHub Actions가 타입·단위 테스트·빌드·Node/Cloudflare 브라우저 검증을 통과한 결과물을 기존 Worker에 자동 배포합니다. Android 패키지는 `android-v버전` 태그에서 별도로 빌드·서명·기기 검사 후 GitHub Releases에 공개합니다. 직원·급여 DB는 Git과 APK에 포함하지 않습니다.

웹 업데이트는 적용 전에 안내하고 새로고침 후 변경 내역을 표시합니다. 여러 릴리스는 스크롤 목록으로 모아서 확인합니다. [업데이트 동작·릴리스 작성](docs/UPDATES.md), [관리자 조회·시스템 점검](docs/SYSTEM_REVIEW.md), [운영·백업](docs/OPERATIONS.md)을 참고하세요.

## 태블릿·PC 관리

로고가 있는 [앱 다운로드 화면](https://feeledu-attendance.feeledu-pj-managing.workers.dev/download)에서도 설치용 APK를 받을 수 있습니다. 설치 화면·홈 화면의 앱 아이콘과 다운로드 페이지는 사용자 제공 FEEL EDU 로고를 사용합니다. Android의 원형 아이콘에서도 글자가 잘리지 않도록 안전 여백을 둡니다.

**기본 배포 경로는 GitHub Releases입니다.** 릴리즈의 Assets에서 APK를 받거나 위의 최신 APK 링크를 누릅니다. [자체 서버 다운로드](https://feeledu-attendance.feeledu-pj-managing.workers.dev/downloads/feeledu-attendance.apk)는 보조 경로입니다. GitHub에 공개한 동일한 서명 APK이며 CI가 체크섬을 검증해 배포합니다. 화면에는 보조 파일의 버전·크기를 표시합니다. 연결 중단 후 재개를 지원하고 APK는 서비스워커에 캐시하지 않습니다. 운영은 Android 10 이상과 최신 Chrome을 권장합니다. 특정 태블릿 모델에 제한하지 않습니다.

태블릿은 `/kiosk`에서 출퇴근하고, 화면 아래 **관리자**로 같은 기기의 관리 화면을 엽니다. PC도 같은 서버의 `/admin`에 접속합니다. 두 기기는 직원·근무·시급·정산을 공유합니다. 태블릿 단독 DB로 분리하지 않습니다.

- **출퇴근·관리자 화면에는 자동 잠금이 없습니다.** 화면 꺼짐은 태블릿 설정에서 관리합니다. 미사용·백그라운드 전환·12시간 경과로 자동 로그아웃하지 않습니다.
- 로그인은 사용 중 자동 연장되며 **로그아웃** 버튼으로 종료합니다. 7일 동안 사용하지 않은 로그인은 만료됩니다. 계정 비활성화·비밀번호 재설정도 기존 로그인을 해제합니다. 브라우저의 로그인 쿠키를 삭제하면 다시 로그인해야 합니다.
- 태블릿에서 **출퇴근 화면**으로 돌아가도 로그인은 유지하며 같은 창에서 숫자패드를 엽니다. PC에서는 별도 창으로 출퇴근 화면을 열 수 있습니다.
- 관리자 조회·수정은 서버 연결이 필요합니다. 연결이 끊겨도 출퇴근 입력은 기존 대기열에 보관하고 복구 후 관리자 확인을 거칩니다.

### 직원별 주간 근무

대시보드에서 주간 날짜를 선택하면 전체 요일별 근무, 직원별 합계, 직원마다 7일 막대그래프를 표시합니다. 개인 그래프는 같은 눈금을 사용하며 표 보기·검색·상태 필터·CSV 다운로드도 제공합니다. 날짜 막대를 누르면 초 단위 출퇴근 시각과 휴게시간을 확인하고 해당 직원의 근무기록으로 이동할 수 있습니다.

완료한 근무와 진행 중인 근무시간을 구분합니다. 서버 시각으로 15초마다 갱신하고, 완료 근무만 주휴 시간 기준에 반영합니다. 24시간 넘게 퇴근하지 않은 기록과 미확인 출퇴근은 확인 대상으로 표시합니다. 한국 시간의 자정·주 경계와 휴게 배분은 급여 계산과 같은 함수를 사용합니다. 휴일 표시는 등록한 휴일 설정을 따릅니다.

### 하루 시급·휴일 근무

**직원·시급 → 월 시급**에서 적용 월을 선택하면 그달 1일부터 다음 시급 변경 전까지 적용합니다. 선택한 달의 기존 월중 기본 시급 변경은 월 시급 하나로 통합하며 다른 달 이력은 보존합니다. **하루 시급**은 별도 버튼에서 관리하며 해당 날짜의 월 시급보다 우선합니다. 다음 날에는 기본 시급으로 돌아가고, 휴일·주휴 계산에도 반영됩니다. 기존 확정 정산본은 보존합니다. [야간 근무·누락 기록·월 시급 안내](docs/NIGHT_SHIFTS.md)를 참고하세요.

**근무기록**에서 조회 기간과 ‘휴일·공휴일 근무’, ‘하루 시급 적용’, ‘퇴근 누락’ 필터를 조합할 수 있습니다. 자정을 넘는 근무도 실제 시간이 겹치는 날짜로 판정하며, 정확히 자정에 끝나면 다음 날 근무로 보지 않습니다. 휴일 여부는 공식 공휴일 저장 자료와 설정에 등록한 날짜·반복 요일을 사용합니다.

**급여·수당 → 계산 내역**에서 날짜별 시간·적용 시급·하루 시급 여부·휴일가산·야간시간·야간가산을 확인합니다. 일별 표시 금액은 참고용이며 지급 계산은 항목별 합산 후 반올림합니다. 과거 확정본은 그대로 보존합니다.

**야간수당**은 22:00~다음 날 06:00 실제 근로에 해당 날짜 시급의 50%를 추가하고 휴일가산과 별도로 합산합니다. 설정에서 가산율을 관리하며, 근무기록의 **실제 휴게 구간 입력**으로 야간에 겹치는 휴게만 정확히 공제합니다. 휴게 합계만 있어 금액이 불명확하면 예상액·확인 경고를 표시하고 정산 확정 전에 구간 입력을 요구합니다. [공식 근거·통상시급 전제·계산 범위](docs/NIGHT_SHIFTS.md)를 참고하세요.

## 로컬 실행

Node.js **24.21 이상 24.x**, npm **11.x**가 필요합니다. 저장소 루트에서 실행하세요.

```powershell
npm ci --ignore-scripts
npm run dev
```

- 관리자: <http://127.0.0.1:3000>
- 태블릿 미리보기: <http://127.0.0.1:3000/kiosk>
- 종료: 실행한 터미널에서 `Ctrl+C`
- 첫 실행 시 `data/feeledu.db`와 `data/setup-token`을 생성합니다. 둘 다 Git에서 제외됩니다.

### 최초 설정

1. 서버 터미널의 **최초 운영자 설정 코드**를 입력하고 본인 계정을 만듭니다. 기본 계정·비밀번호는 없습니다.
2. **설정 → 학원 공통 계산 기준**에서 실제 사용할 조건과 산식을 확인·저장합니다. 확인 전에는 정산 확정이 차단됩니다.
3. **설정 → 관리자 계정**에서 부장님 계정을 만들고 직접 전달합니다. 새 비밀번호는 10자 이상이며 특수문자를 1개 이상 포함해야 합니다.
4. **직원·시급 → 조교 등록**에서 이름, 전화번호 뒷자리, 최초 시급과 적용 월을 입력합니다.
5. **설정 → 휴일·공휴일**에서 공휴일 연결 상태를 확인하고 학원 자체 휴일을 추가합니다. 자동 반영에는 서버의 `KASI_SERVICE_KEY`가 필요합니다. [인증키 발급·연결 안내](docs/HOLIDAY_API.md)를 참고하세요.
6. **설정 → 태블릿 연결**에서 코드를 발급하고 태블릿의 `/kiosk`에서 입력합니다. 코드는 10분간 한 번만 사용할 수 있습니다.

태블릿에서 번호를 입력하고 본인 이름을 확인한 뒤 출근·퇴근을 누릅니다. `0012` 같은 번호도 유지합니다. 중복 번호는 이름을 선택하며 동명이인은 구분되는 표시 이름을 사용하세요.

## 급여 계산 규칙

아래는 요청에 맞춘 **학원 운영 산식**입니다. 자동 법정 급여 판정 엔진은 아닙니다. 실제 계약과 지급 조건에 맞게 관리자가 설정·검토해야 합니다.

- 날짜·주 경계는 한국 시간(`Asia/Seoul`), 시각 저장은 UTC입니다.
- 실제 근무시간에서 입력한 실제 휴게시간만 제외합니다. 자동 공제하지 않습니다.
- 날짜를 넘는 근무는 날짜·시급·휴일 구간으로 나눕니다. 총 휴게시간은 구간별 시간 비율로 나눕니다.
- 기본급: `유급 근무시간 × 해당 날짜 적용 시급`.
- 휴일 추가 가산: `휴일 기본급 × (배율 - 1)`. 1.5배이면 기본급 외 50%를 추가합니다. 개인별 배율을 공통 배율보다 우선합니다.
- 공식 공휴일·등록한 휴일·반복 요일이 겹쳐도 가산은 한 번만 적용합니다. 인증키 등록 후 한국천문연구원 자료의 공휴일·대체/임시공휴일을 자동 반영합니다. 갱신 실패 시 기존 자료를 유지하며, 기존 휴일 삭제는 관리자 검토를 거칩니다. 인증키 등록 전에는 자동 연결되지 않습니다.
- 주휴는 **해당 주 실제 근무** 기준입니다. 초기 제안값: 주 15시간 이상이면 `min(주 실근무시간, 40) ÷ 5 × 해당 주 기본급 가중평균 시급`. 시간 기준·상한·나눗수·주 시작 요일을 설정할 수 있습니다.
- 주중 시급 변경 시 `해당 주 기본급 ÷ 해당 주 실근무시간`의 가중평균 시급을 사용합니다. 개인별 주휴 제외도 가능합니다.
- 주휴는 **그 주의 마지막 날**에 귀속합니다. 월 경계에서도 전체 주를 계산하고 그 주 마지막 날이 속한 조회 기간에 반영합니다.
- 기본급·휴일가산·주휴수당을 각각 합산한 뒤 원 단위 반올림합니다. 기타 수당·조정은 정수 원 단위입니다.
- 세전 급여만 계산합니다. 세금·보험 공제, 이체, 연장·야간 가산, 유급휴가·미근무 유급휴일 임금은 자동 계산 범위에 포함하지 않습니다.

### 소급 변경·정산

월 시급에서 적용 월과 사유를 지정하면 해당 월 1일부터 다시 계산합니다. 하루 예외는 하루 시급에서 별도로 정정합니다. **확정한 정산은 덮어쓰지 않고** 현재 계산과 최근 확정의 차액을 표시합니다. 동일 기간에 새 버전으로 차액 정산할 수 있으며 과거 확정본도 열람할 수 있습니다.

서로 겹치는 다른 기간의 정산은 차단합니다. 기존과 동일한 기간을 선택해 재정산하세요. 진행 중인 날짜·미확인 출퇴근·미완료 근무·시급 누락·미확인 계산 기준이 있으면 확정할 수 없습니다. 정산 확정은 이체를 의미하지 않습니다. CSV에는 현재 계산액·이전 확정액·차액이 포함됩니다.

## 오프라인·기기 변경·업데이트

- 태블릿 입력은 **IndexedDB에 먼저 저장**한 뒤 전송합니다. 새로고침·앱 종료 후에도 같은 브라우저 프로필에서 대기열을 읽습니다.
- UUID로 중복을 검사하므로 서버 응답만 유실돼 재전송해도 한 번만 처리합니다.
- 재연결 후 입력 순서대로 전송하며 전송 대기 건수와 서버 저장 완료를 별도로 표시합니다.
- 오프라인·전송 지연·기기 시각 차이·출퇴근 순서 충돌은 **관리자 확인 전 급여에 합산하지 않습니다.**
- 관리자는 기기 시각을 확인하고 출근 → 퇴근 순서로 승인하거나 반려합니다. 기존 근무와 겹치면 수동 정정 후 반려할 수 있습니다.
- 새 화면 버전은 실행 시·온라인 복귀·화면 복귀와 5분 주기로 확인합니다. 출퇴근 입력·연결 코드 입력·저장·전송 중이 아니고 실제 기기 대기열이 비어 있으며 1분간 조작이 없으면 자동 적용합니다. ‘업데이트 확인/적용’도 제공합니다. 새 버전 교체는 기존 IndexedDB와 연결 토큰을 지우지 않습니다.
- 화면·계산 기능 변경은 서버 배포로 반영합니다. Android 패키지 자체 변경은 GitHub Releases의 새 APK를 기존 앱 위에 설치합니다. 매번 APK를 다시 설치하거나 앱을 삭제할 필요가 없습니다.
- **태블릿 연결 해제 전에 전송 대기 0건을 확인하세요.** 연결 해제 후에는 새 입력·전송이 차단됩니다.
- 미전송 기록은 **기록 보관**으로 JSON을 내보내고, 관리자 **근무기록 → 복구 파일 가져오기**에서 복구합니다(한 번에 최대 200건). 복구 후에도 승인해야 반영되며 같은 파일을 다시 가져와도 중복되지 않습니다.
- 관리자 복구 완료 후 **복구 확인 후 재연결**로 새 코드를 입력합니다. 기존 대기열의 기기 보관본도 남깁니다.
- 브라우저 데이터 삭제·공장 초기화·기기 고장 전에 전송 또는 파일 보관이 필요합니다. 서버가 받지 못한 기록은 기기 데이터 삭제 시 복구할 수 없습니다.
- 전송 대기가 0건일 때 업데이트를 적용합니다. 앱 셸만 캐시하고 인증·급여 API 응답은 캐시하지 않습니다.

## 실제 안드로이드 운영

Android Chrome에서 **HTTPS 주소**로 열고 ‘홈 화면에 추가/앱 설치’를 선택합니다. PC를 서버로 사용하면 그 PC가 계속 켜져 있어야 합니다.

`127.0.0.1`은 접속하는 기기 자신을 가리킵니다. 태블릿에 이 주소를 입력해 PC에 접속할 수는 없습니다. 또한 `http://192.168…` 일반 LAN 주소는 설치·오프라인 기능을 위한 안전한 컨텍스트가 아닙니다. 태블릿은 이런 주소에서 HTTPS 안내를 표시합니다. [MDN 안전한 컨텍스트](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)

### 단일 서버 + 영구 디스크 + HTTPS

GitHub Pages 단독으로는 API·DB를 운영할 수 없습니다. Node 서버를 계속 실행할 호스팅과 영구 저장소가 필요합니다. 서버리스 임시 디스크나 OneDrive 동기화 폴더를 실제 운영 DB 위치로 사용하지 마세요. 개발 코드가 OneDrive에 있는 것은 별개이며 `DB_PATH`로 운영 DB 경로를 지정할 수 있습니다.

Docker와 도메인이 준비된 서버에서는 다음 구성으로 시작할 수 있습니다. 이 PC에서 Docker 설치나 실제 배포를 수행하지는 않았습니다.

1. 도메인 DNS를 서버로 연결하고 80·443 포트를 개방합니다.
2. 서버에서 저장소를 내려받고 `.env`에 `DOMAIN=attendance.example.com`처럼 실제 도메인을 지정합니다(프로토콜·경로 제외).
3. 실행합니다.

```sh
docker compose up -d --build
docker compose logs app
```

표시된 초기 설정 코드로 `https://실제도메인`에서 운영자를 만듭니다. 태블릿은 `/kiosk`로 연결합니다. Caddy가 HTTPS 인증서 발급·갱신과 HTTP 리디렉션을 처리하고 앱 서버는 외부에 직접 노출하지 않습니다. [Caddy HTTPS 문서](https://caddyserver.com/docs/automatic-https)

- DB·백업은 `academy_data` 볼륨에 보관합니다. 재빌드해도 유지합니다. **`docker compose down -v`는 데이터를 삭제하므로 사용하지 마세요.**
- `.env`, `data/`, DB, 백업, 비밀번호는 커밋하지 않습니다. Git·Docker 제외 규칙에 반영돼 있습니다.
- 직접 프록시를 구성한다면 `PUBLIC_ORIGIN`을 실제 HTTPS 주소로 설정하고 신뢰할 프록시 한 단계에서만 `TRUST_PROXY=1`을 사용합니다.
- 운영은 `COOKIE_SECURE=true`를 유지합니다. `false`는 로컬 운영 빌드 검사 전용입니다.
- 환경변수는 `.env.example`을 참고하세요. 여러 서버에서 SQLite 파일 하나를 공유하지 않습니다.

### 업데이트 순서

1. 태블릿 대기·관리자 확인 목록을 점검하고 전체 백업을 받습니다.
2. GitHub 검사 결과를 확인하고 운영 서버의 코드를 갱신합니다.
3. `docker compose up -d --build`로 새 버전을 실행합니다. 데이터 볼륨은 유지합니다.
4. 태블릿에 업데이트를 적용하고 기록·시급·정산을 확인합니다.

DB는 버전 테이블과 마이그레이션을 사용합니다. 더 최신 스키마를 이전 앱으로 여는 것은 차단합니다. 이전 코드로 돌아갈 때는 호환되는 백업이 필요합니다.

## 백업·복구

- 로컬/자체 서버는 시작 시와 매시간 점검해 실행 중인 날 하루 한 번 일관성 백업을 만듭니다. DB 옆 `backups/auto-YYYY-MM-DD.db`에 최근 30개를 보관합니다.
- Cloudflare 운영은 영구 SQLite와 공급자의 시점 복구 기능을 사용하며, 전체 백업 다운로드는 검사값을 포함한 JSON입니다. [운영·복구 절차](deploy/CLOUDFLARE.md)를 따릅니다.
- 자동 백업도 같은 디스크에 있으므로 운영자는 **전체 백업 받기**로 별도 장소에 보관하세요.
- 다운로드는 SQLite 백업 API를 사용합니다. 관리자 계정·근무·급여·태블릿 연결 정보를 포함하므로 접근을 제한하세요.
- 복구 전 서버를 완전히 중지하고 기존 데이터 폴더/볼륨 전체를 별도 보관합니다. **새 빈 폴더/볼륨**에 백업을 `feeledu.db`로 놓고 그 위치를 사용하도록 설정해 재시작합니다. 기존 `-wal`·`-shm` 파일과 섞지 마세요.
- 먼저 별도 위치에서 복구를 확인하세요. 테스트에는 백업 파일을 새 DB로 열어 무결성과 직원 데이터를 확인하는 검증이 포함됩니다.

## 검증

```powershell
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

API·계산 테스트는 권한·로그아웃·CSRF·중복 번호·날짜·겹친 근무·동시 수정·오프라인 승인/복구·소급 변경·월 경계·정산 보존·백업 복구를 검사합니다. 브라우저 테스트는 최초 설정부터 관리자·직원 등록, 연결, 출퇴근, 오프라인 새로고침·재전송·승인까지 실행합니다.

자동 테스트는 인메모리·임시 DB를 사용합니다. 브라우저 테스트 서버는 4173/4175 포트입니다. 사용자의 배포 후 수동 테스트 요청으로 공개 앱에 남긴 `[테스트]` 가상 직원·기록은 실제 급여 자료와 구분합니다. GitHub Actions는 `main` 검증 성공 후 기존 Cloudflare 서버를 자동 업데이트하며, APK는 별도 Android 릴리즈 워크플로로 공개합니다.

Windows에서 로컬 실행·브라우저 검증했습니다. Linux Docker 빌드와 실제 안드로이드 기기는 별도 확인이 필요합니다.

## 코드 구조

제공된 FEEL EDU 로고 원본은 `public/brand/feeledu-logo.png`에 보관하고 공통 `Brand` 컴포넌트에서 표시합니다. 설치용 아이콘은 원본을 변경하지 않고 `npm run icons`로 생성합니다(Playwright Chromium 필요). 화면 공통 입력은 `Field`, 상세 설명 접기는 `Help` 컴포넌트에서 관리합니다.

- `src/admin/`: 관리자 화면·설정·편집 폼·데이터 컨텍스트
- `src/Kiosk.tsx`, `src/kiosk-store.ts`: 숫자패드·IndexedDB 대기열·복구
- `src/api.ts`: 통신·오류 처리
- `server/app.ts`: HTTP 보안·속도 제한·라우트 연결·백업 다운로드
- `server/routes.ts`: 인증·권한·입력 검증·업무 API
- `server/db.ts`: 스키마·마이그레이션·트랜잭션·감사 이력
- `server/payroll.ts`: 날짜별 시급·휴일·주별 수당·정산 계산
- `server/security.ts`, `server/index.ts`: 비밀번호·토큰 및 실행·자동 백업
- `shared/`: 공통 타입·한국 시간 계산
- `tests/`: API·계산·브라우저 검증
- `scripts/`, `deploy/`: 빌드·아이콘·운영·테스트 실행과 HTTPS 설정
