# 필에듀 운영·백업

## 현재 운영 구조

Android 앱·Chrome과 PC 관리자가 같은 Cloudflare Worker에 접속한다. 기록은 기존 `Academy` SQLite Durable Object(`feeledu-primary`)에 영구 저장한다. 노트북 전원과 무관하다. GitHub `main` 검증 성공 후 기존 Worker를 자동 배포한다. 이번 변경은 웹·서버 변경이므로 APK 재설치가 필요 없다. 태블릿은 입력·미전송 기록이 없는 안전한 시점에 웹 업데이트를 적용한다.

공휴일 자동 반영을 위해 DB와 새 백업은 schema 4를 사용한다. 기존 schema-3 백업도 새 앱에서 복구할 수 있다. 직원·계정·급여·근무 테이블의 기존 기록은 보존하며 공식 공휴일과 갱신 상태 테이블을 추가한다. schema-3 전용 구버전은 schema-4 DB를 열지 않으므로 롤백에는 호환 버전 또는 검증한 백업 복원이 필요하다. Worker/DO 이름·바인딩·네임스페이스는 유지한다.

## 읽기·쓰기 절감

- 태블릿 대기 조회 및 주간 대시보드 갱신: 60초. 입력 후 즉시 전송·명단 갱신. 숨겨진 화면의 정기 조회 중지, 화면 복귀 시 갱신.
- 근무기록 자동 조회: 근무·승인 대기 두 항목만 갱신. 초기 조회·수동 새로고침·수정 후에는 전체 정보 갱신. 중복 실행 방지와 기간 변경 시 취소.
- 미전송 재시도: 15초부터 최대 5분까지 지연, 429의 `Retry-After` 준수. 연결 해제된 토큰의 자동 재시도 중지. 기록은 성공 응답 후에만 기기 큐에서 제거한다.
- 여러 탭의 전송은 Web Locks 지원 시 직렬화한다. 미지원 브라우저에서도 서버의 요청 UUID와 DB 트랜잭션·유일 인덱스가 같은 요청의 중복 근무 생성을 막는다.
- 같은 UUID의 내용 변경·다른 기기 재사용은 409. 다른 UUID로 중복 출근하면 승인 대기 기록으로 보존하며 추가 근무는 생성하지 않는다. 직원에게 오프라인 기록이 실제 근무에 반영됐다고 표시하지 않는다.
- HTML·빈 본문·필수 필드가 없는 JSON의 HTTP 200은 출퇴근 수신 확인으로 인정하지 않는다. 원래 UUID의 미전송 기록을 보존하고 재시도한다.
- 기기의 최근 연결 시각은 5분 단위로 기록한다. 요청 제한을 초과한 요청은 제한 카운터를 계속 증가시키지 않는다.
- 기간 조회는 종료 시각 인덱스의 열린 근무/종료된 근무 두 범위를 합친다. 오래 열린 근무도 누락하지 않는다. 승인 대기 전용 부분 인덱스는 정상 출퇴근 기록의 증가와 분리된다.
- 급여는 기간 시작에 적용되는 시급 + 기간 내 변경분, 해당 기간의 하루 시급만 읽는다. 주휴 계산을 위해 첫 주 시작일부터 읽는다. 감사 이력은 최근 200건만 인덱스로 조회한다.

## 조회 비용 검증 (2026-11-12)

`tests/query-cost.test.ts`는 배포 코드와 분리된 로컬 Miniflare/Workerd SQLite에 근무 29,201건, 출퇴근 58,401건, 하루 시급 29,200건, 감사 이력 20,000건, 직원 20명을 생성한다. SQL cursor의 `rowsRead`/`rowsWritten`으로 측정한다. 원본 쿼리와 결과·급여 지문이 같은지 검사한다. 동일 시각인 목록 행의 정렬 순서는 제외한다. 운영 DB에 테스트 기록을 넣지 않는다.

| 조회 1회          | 이전 읽기 행 | 개선 후 읽기 행 |
| ----------------- | -----------: | --------------: |
| 주간 근무         |       87,645 |             110 |
| 월 급여           |      146,085 |             540 |
| 월 근무기록       |       29,298 |             290 |
| 승인 대기         |       58,402 |               1 |
| 최근 변경 이력    |       40,000 |             200 |
| 출근 시 겹침 검사 |       29,201 |               2 |

모두 위 조회 자체의 쓰기는 0이다. HTTP 인증·요청 제한·기기 연결 시각·로그인 등 부대 비용은 이 표에 포함하지 않는다. 숫자는 가상 데이터의 로컬 측정값이며 실제 계정 사용량이 아니다. 재실행 결과는 `.tmp/query-cost.json`에 저장된다.

직원 8명이 매일 출퇴근하면 업무 이벤트는 하루 16건, 매일 운영해도 연 5,840건이다. 24시간 켜진 태블릿 1대의 정상 정기 조회는 약 1,440회/일(기존 5,760회), 관리자 2명이 각각 2시간 대시보드를 켜면 약 240회/일이다. 인증·요청 제한 등 부대 읽기/쓰기를 포함해도 이 규모의 정상 운영은 아래 DB 무료 한도에 여유가 있다. 예외적으로 승인 대기가 대량 누적되면 목록을 다시 읽으므로 정기적으로 처리한다.

2026-11-12 확인한 Cloudflare 공식 무료 한도는 SQL 읽기 500만 행/일, 쓰기 10만 행/일, 계정 SQL 저장 공간 5GB, DO 요청 10만/일 및 계산량 13,000GB-s/일이다. 한도는 해당 계정의 다른 앱과 공유한다. 요청 제한 및 인덱스 변경도 비용에 포함되므로 업무 이벤트 수와 과금 행 수는 같지 않다. 계산량도 별도 한도이며 단일 128MiB DO가 하루 내내 활성 상태라고 보수적으로 가정하면 약 11,059GB-s다. 데이터베이스 사용량만으로 전체 서비스 용량을 보장하지 않는다.

Free 한도를 넘으면 해당 연산이 실패하며 자동 유료 전환되지는 않는다. 일일 한도는 한국 시각 오전 9시에 초기화된다. Cloudflare 대시보드에서 계정의 실제 요청·저장 공간·읽기/쓰기·계산량을 확인한다. 가격·정책 변경이나 다른 앱 추가 시 다시 확인한다.

공식 자료: [요금 및 무료 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/), [SQL 행 수·인덱스 과금·30일 복구](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/).

## 백업 받기·검사

1. 운영자로 로그인해 상단 **백업**, 또는 **설정 → 전체 백업 받기**를 누른다.
2. 현재 비밀번호를 입력한다. 클라우드에서는 JSON, 로컬 Node 서버에서는 SQLite `.db` 파일을 받는다. 관리자(manager)는 전체 백업에 접근할 수 없다.
3. 다운로드 완료와 저장 위치를 확인하고, PC 또는 접근 권한이 제한된 별도 저장소에 보관한다. 전체 백업에는 관리자 비밀번호 검증값과 개인정보·급여가 포함되므로 GitHub에 올리지 않는다.
4. 클라우드 JSON 파일은 **설정 → 백업 파일 검사 (JSON)**에서 생성일·직원·근무·출퇴근 건수와 SHA-256 검사값을 확인할 수 있다. 파일은 브라우저 안에서만 읽으며 업로드하지 않는다. 검사값은 우발적 손상 검사이며 작성자 인증·연결 관계의 완전한 복구 검증을 대신하지 않는다.

‘최근 생성’은 서버의 백업 생성 이력이며 사용자의 다운로드 완료를 보증하지 않는다. 이력이 없거나 30일이 지나면 안내한다. 기기 안에 남은 **미전송** 기록은 서버 전체 백업에 들어 있지 않다. 태블릿에서 별도로 미전송 복구 파일을 보관하고 관리자의 복구 기능으로 처리한다.

월 정산 후, 시급 대량 수정 전 백업을 권장한다. 자동으로 다른 저장소에 사본을 복제하는 기능은 이번 작업에 포함하지 않았다. Cloudflare SQLite의 최근 30일 PITR은 별도 복구 수단으로 제공되지만 독립 보관한 파일을 대체하지 않는다.

## 복구 검증

클라우드 JSON을 새 로컬 DB로 검증할 때:

```powershell
node scripts/restore-snapshot.mjs <백업.json> <새로운-검증용.db>
```

새 경로만 허용하며 기존 운영 DB를 덮어쓰지 않는다. 검사값·테이블/열 허용 목록·참조 무결성과 SQLite `integrity_check`를 검사한다. 운영 서버 복원은 이 검증 후 별도 진행한다. 검증 DB 역시 개인정보를 포함하므로 안전하게 보관한다. 세션·로그인 실패 카운터·요청 제한 등 운영 보조 상태는 JSON 이전 대상에서 제외되어 재로그인이 필요하다. 업무 변경 이력(audit)은 백업에 포함된다.

JSON 복구 형식은 테이블별 100,000행을 허용하며 브라우저 검사는 50MB까지다. 수년 후 이 한도에 근접하면 백업의 분할·스트리밍 및 보관 정책을 확장한다. 이 한도를 넘는다고 근무 데이터가 자동 삭제되는 것은 아니다.
