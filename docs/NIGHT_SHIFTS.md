# 야간 근무·누락 기록·월 시급

## 자정을 넘는 출퇴근

22시 출근, 다음 날 04시 퇴근은 한 근무 6시간으로 저장한다. 근무 중 상태는 날짜가 아닌 미종료 기록으로 판단하므로 00시에 초기화하지 않는다. 새로고침·다음 날 명단 조회에도 같은 기록을 사용한다. 날짜별·주별·월별 조회에서는 출근일 2시간, 퇴근일 4시간으로 나눈다. 실제 휴게 구간을 입력하면 겹치는 시간만 공제한다. 합계만 있는 기존 기록은 비례 배분하며 아래의 야간 정산 확인을 적용한다.

## 야간 가산수당 (2026-11-14 확인)

[고용노동부의 근로기준법 제56조 안내](https://1350.moel.go.kr/rtmview.do?id=1000320245)에 따르면 야간근로는 한국 시간 **22:00부터 다음 날 06:00까지 실제 근로**이며 통상임금의 **50% 이상을 추가**한다. 휴일·연장과 겹쳐도 야간 가산은 별도로 더한다. 22시는 포함하고 06시는 제외한다. 법정 가산 적용은 원칙적으로 상시 5인 이상 사업장 기준이며, 이 앱은 직원 목록의 인원으로 적용 여부를 판단하지 않고 요청한 학원의 지급 정책으로 전 직원에게 야간 계산을 기본 활성화한다.

**설정 → 야간근로**에서 사용 여부와 추가 가산율을 관리한다. 기본값은 `0.5 = 50%`, 더 높은 가산율도 가능하다. 산식은 `실제 야간 근로시간 × 해당 날짜 등록 시급 × 추가 가산율`이다. 현재 월 시급·하루 시급을 가산 기준 시급으로 사용한다. 고정수당 등으로 실제 통상시급과 등록 시급이 다르면 이 산식의 전제가 달라지므로 지급 전 확인해야 한다. 이 앱이 통상임금의 법적 구성항목을 자동 판정하지 않는다.

| 시급 12,000원 / 실제 휴게 없음                  | 기본급 | 휴일 추가 | 야간 추가 | 합계 (주휴·기타 제외) |
| ----------------------------------------------- | -----: | --------: | --------: | --------------------: |
| 일반일 22:00~다음 날04:00                       | 72,000 |         0 |    36,000 |               108,000 |
| 22:00~24:00가 휴일, 다음 날00:00~04:00는 일반일 | 72,000 |    12,000 |    36,000 |               120,000 |

기본급은 한 번만 넣는다. 휴일 1.5배와 야간 50%를 곱해 2.25배로 만들지 않는다. 야간 수당은 주휴 평균 시급의 기본급 분자에 다시 넣지 않는다. 자정·06시·22시·주·월·시급·공휴일 경계에서 나눠 계산하고, 항목별 전체 기간 합계에만 원 단위 반올림한다. 화면의 날짜별 원 단위 표시는 참고값이다.

### 실제 휴게와 기존 기록

[고용노동부 휴게시간 안내](https://1350.moel.go.kr/rtmview.do?id=1000111373)에 따라 실제로 자유롭게 사용한 휴게만 제외하며, 법정 휴게가 필요하다는 이유로 앱이 자동으로 분을 빼지 않는다. **근무기록 → 정정 → 실제 휴게 구간 입력**에서 한국 날짜·시각으로 최대 10구간을 입력한다. 합계는 자동 계산한다. 근무 밖 구간·역전·중복·겹침·합계 불일치는 서버에서 거부한다. 휴게 구간과 근무 변경은 같은 트랜잭션으로 저장하고 revision과 사유 이력을 남긴다. 구버전 탭의 메모 정정도 저장된 구간을 삭제하지 않는다.

예를 들어 21:00~07:00에 휴게 60분만 알면 야간 휴게가 0분인지 60분인지 알 수 없다. 이때는 비례 **예상액**과 확인 경고를 보여 주고 정산 확정을 거부한다. 날짜를 넘는 야간 기록에 합계만 있는 경우에도 날짜별 시급·공휴일 배분 확인을 위해 실제 구간을 요구한다. 같은 날짜의 전 구간이 야간이면 합계만으로 야간 근로시간을 확정할 수 있다. 휴게가 없으면 별도 구간 입력이 필요 없다. 진행 중 기록은 확정 급여에 넣지 않는다.

급여 표·직원별 계산 내역·날짜별 내역·CSV·새 확정본에 야간시간과 야간 가산을 분리한다. 정책이나 시급을 소급 변경해도 과거 확정 JSON은 그대로 보존하고 차액을 계산한다. 야간 항목이 없었던 이전 확정본은 `0`으로 표시한다.

### 계산 범위

이번 변경은 야간 가산을 추가한다. 기존 휴일 배율과 실제 주간 근무 기준 주휴 정책을 유지한다. 일8시간·주40시간 초과 연장 가산, 휴일8시간 초과 가산의 자동 판정이나 단시간 근로계약의 소정시간 초과 판정은 별도 기능이다. 법정 지급 여부·통상임금 구성·연속 야간근로의 휴일 귀속까지 모두 검증하는 법정 급여 엔진은 아니다. 필요한 차액은 기타 수당에 사유를 남겨 별도 반영한다.

한국 시각을 기준으로 각 날짜의 시급·하루 예외·휴일 배율을 적용한다. 일요일~월요일이나 월말~다음 달도 같은 원칙으로 나눈다. 24시간이 넘는 미종료 기록은 확인 필요로 표시하며 자정에 자동 종료하거나 삭제하지 않는다. 관리자가 실제 날짜·시간을 확인해 정정한다.

## 출퇴근을 누락했을 때

- 둘 다 누락: **근무기록 → 출퇴근 직접 입력**에서 직원과 출근·퇴근 날짜/시간, 실제 휴게, 사유를 입력한다.
- 퇴근만 누락: 기존 **근무 중** 기록의 **정정**에서 실제 퇴근 날짜/시간을 입력한다. 같은 구간을 새 기록으로 중복 등록하지 않는다.
- 새벽 퇴근: 퇴근 날짜도 다음 날로 선택한다. 같은 날 22시~04시로 입력했으면 **퇴근을 다음 날로 변경** 버튼을 제공한다. 저장 전 구간과 다음 날 여부를 표시한다.

시간 역전, 미래 시각, 24시간 초과, 다른 기록과 겹침, 전체 근무보다 긴 휴게는 거부한다. 진행 중인 기록은 퇴근을 비울 수 있다. 두 관리자가 동시에 정정하면 revision이 다른 저장을 거부한다. 메모·휴게만 바꾸면 원래 서버 시각의 초·밀리초를 그대로 보존한다. 모든 등록·정정에는 사유와 관리자 이력이 남는다.

승인 대기 출퇴근이 별도로 남아 있다면 수동 입력 기록과 비교해 처리한다. 승인 대기는 실제 근무에 포함되지 않으며 이미 보완한 구간을 다시 승인하면 중복 검사로 차단한다.

## 월 시급과 하루 예외

**월 시급**은 선택 월 1일부터 다음 저장된 시급 변경 전까지 유지한다. 해당 월의 기존 날짜별 기본 시급 변경이 있으면 화면에 통합 대상을 알리고 월 시급 하나로 정리한다. 다른 달 이력과 하루 시급은 수정하지 않는다. 저장 시 해당 월 이력 전체를 다시 비교해 오래된 관리자 화면의 덮어쓰기를 거부한다. 과거 확정 정산본은 보존하고 현재 금액과의 차액을 계산한다.

**하루 시급**은 별도 화면에서 관리하며 선택한 날짜에만 우선 적용한다. 자정이 지나면 다음 날 기본 시급을 사용한다. 월 시급을 수정해도 하루 예외는 유지한다. 예외를 해제해야 월 시급을 사용한다. 이미 저장된 다른 달의 월중 변경은 과거 이력으로 표시하며 그 달을 수정할 때만 통합한다.

기존에 열려 있는 이전 앱과 과거 데이터 호환을 위해 날짜 기준 API는 유지한다. 새 관리자 화면은 월 기준 API를 사용한다. 기존 시급 이력을 배포만으로 일괄 변경하지 않는다.

## 태블릿 대기와 관리자 로그인

출퇴근·관리자 화면은 자동 잠금 없이 유지하며 앱이 화면 전원을 끄지 않는다. 실제 화면 꺼짐·충전·밝기는 기기 설정으로 관리한다. 관리자도 미사용·백그라운드 전환·12시간 경과로 자동 로그아웃하지 않는다. 로그아웃 버튼·계정 비활성화·비밀번호 재설정으로 세션을 종료한다. 태블릿에서 출퇴근 화면으로 돌아가도 로그인은 유지한다.

새 로그인은 유지 모드로 발급한다. 아직 유효한 이전 세션은 새 화면 최초 접속 시 본인 세션만 유지 모드로 전환한다. 이 모드에는 유휴·12시간 상한이 없고 쿠키·서버 토큰은 7일 유효기간을 사용 중 자동 갱신한다. 갱신은 기존 인증 API 요청에서 하루 최대 한 번만 쓰며 기존 만료 시각으로 판단하므로 서버 재시작에도 반복 쓰지 않는다. 정적 관리자 화면을 계속 열어 두면 하루 한 번 상태를 확인해 로그인 유지를 이어 간다. 7일 동안 사용하지 않은 로그인은 만료되고, 브라우저 쿠키가 지워지면 재로그인한다. 세션은 업무 백업에 포함하지 않는다. 구 API에서 유지 옵션을 생략한 임시 로그인은 기존 제한을 적용한다.

## 테스트 데이터 정리

운영자 전용 `/api/admin/test-data`가 `[테스트]` 표시 직원과 연결된 행의 개수만 미리 보여 준다. 표시 안의 공백도 인식한다. `/api/admin/test-data/cleanup`은 현재 비밀번호·사유·변경되지 않은 계획 지문을 요구한다. 해당 직원의 출퇴근·근무·시급·하루 시급·수당을 한 트랜잭션으로 정리한다. 일반 직원·설정·기기·관리자 계정은 삭제하지 않는다. 확정 정산본이나 다른 직원 기록과 연결되어 있으면 정리를 거부한다. 삭제 작업의 감사 이력은 보존한다.

기기 안의 미전송 기록은 서버 정리와 별개다. 삭제된 테스트 직원의 오래된 미전송 기록도 자동으로 버리지 않는다. 정리 전에는 태블릿 연결·미전송 상태를 확인하고, 필요하면 기기에서 복구 파일을 보관한다. 서버 정리는 태블릿 토큰이나 실제 직원의 미전송 큐를 초기화하지 않는다.

직원을 찾을 수 없는 미전송 항목은 원래 UUID·시각을 유지한 채 기기에 남기고 5분 후 재시도한다. 같은 직원의 뒤 항목도 순서를 유지해 보류하지만 다른 직원 기록은 계속 전송한다. 이 항목만 남았으면 명단은 분당 한 번까지만 조회한다. 관리자 확인 안내와 복구 파일 보관 기능을 제공하며, 미전송 항목이 남은 동안 자동 업데이트는 보류한다.
