# 시스템 점검 — 2026-11-13

## 이번 변경

관리자 화면은 모든 자료를 일괄 조회하던 방식에서 화면별 조회로 바꿨다. 클라이언트 캐시는 로그인 세션의 RAM에만 존재한다. 서버의 권한·기간 검증·변경 충돌 검사를 대신하지 않는다.

| 상황                     | 이전                                  | 변경 후 및 검증                                                     |
| ------------------------ | ------------------------------------- | ------------------------------------------------------------------- |
| 첫 대시보드              | 11개 관리자 자료 + 주간 현황          | 설정 + 주간 현황, GET 2회                                           |
| 직원 화면 재방문         | 전체 재조회                           | 유효 캐시가 있으면 추가 직원 GET 0회                                |
| 기록 화면 기간 연속 변경 | 전체 자료 재조회                      | 200ms 후 마지막 기간 기록 GET 1회, 공통 자료 재사용                 |
| 기록 화면 1분 갱신       | 기존에도 기록·승인 대기만 갱신        | 이 동작 유지, 공통 캐시가 유효하면 두 GET만 발생                    |
| 자료 수정                | 전체 재조회                           | 영향받는 자료를 무효화하고 현재 화면의 필요 자료만 갱신             |
| 공휴일 상태·목록 불일치  | 상태 효과와 전체 갱신이 재실행될 여지 | 같은 버전은 한 번만 목록 재조회, 지연된 응답으로 반복 호출하지 않음 |
| 기간 전환·로그아웃       | 늦은 응답 무시 일부 적용              | 불필요 요청 취소, 키별 결과 분리, 캐시 삭제·지연 응답 덮어쓰기 방지 |

브라우저 테스트는 실제 요청 경로를 수집해 위 횟수를 검사한다. 최초 진입 측정은 로그인·앱 정적 파일·서비스워커 확인을 제외한 업무 자료 GET 수다. 공휴일 불일치 테스트는 브라우저에서 상태 응답만 가공하고 목록 응답을 지연시키며 운영 DB를 수정하지 않는다.

## 함께 확인하는 경계

- 출퇴근 재시도·여러 탭·동시 클릭: 기기별 큐와 요청 UUID, 서버 트랜잭션·유일 인덱스를 유지한다. 응답 유실·HTML 200·429 후 같은 UUID를 재시도하며 확인 전 큐를 지우지 않는다.
- 급여 정확성: 자정·주·월·시급 경계, 하루 시급 우선 적용, 주휴·휴일 계산, 확정 정산 보존, 지문·revision을 통한 오래된 양식 거부를 기존 회귀 테스트로 확인한다. 다른 기간을 선택했을 때 이전 합계를 표시하지 않는다.
- 인증: 운영자·관리자 권한 분리, 다른 출처의 쓰기 차단, 로그인 지연을 유지한다. 이후 사용자의 명시적 요청으로 새 관리자 화면은 로그인 유지 모드로 변경했다. 직접 로그아웃·계정 해제는 계속 적용하며, 구 API 임시 세션의 유휴·최대 시간 제한도 유지한다. 자세한 정책은 NIGHT_SHIFTS.md를 참고한다.
- 공휴일: 고정 공식 HTTPS 원본, 제한된 시간·페이지·크기, 전체 연도 검증·원자 적용, 오류 시 이전 목록 유지, 삭제 변경 검토를 유지한다. 실제 Workerd 네이티브 fetch를 통과하는 테스트로 런타임 차이를 검사한다. 비밀키는 서버 환경에만 둔다.
- 데이터 규모: SQLite 범위·부분 인덱스와 읽기 행 수 검증을 유지한다. 최근 변경 이력은 200건이며 기간 조회는 최대 1년이다. 전체 자료를 클라이언트에 미리 내려받지 않는다.
- 백업: 전체 백업은 운영자 재인증이 필요하다. 검사·복구 테스트는 별도 DB에서 수행한다. 원본 운영 DB·DO 식별자·태블릿 기기 연결은 변경하지 않는다.

## 운영상 범위

2026-11-14 표시 개선: 근무기록의 한국 날짜·요일에 토요일 파란색, 일요일·공식/수동 휴일 빨간색을 적용한다. 토요일 공휴일은 빨간색이 우선하며 자정을 넘는 퇴근 날짜도 별도로 판정한다. 공식 목록에 반영된 대체·임시공휴일은 별도 브라우저 API 호출 없이 같은 공휴일 캐시를 사용한다. 앱 실행 모드별 다운로드 안내와 본인 프로필 변경 시 권한·세션·부장님 계정 보존을 격리 테스트 및 Node/Workerd 브라우저에서 확인한다. 새 고정 휴일 목록을 프론트에 하드코딩하지 않는다.

2026-11-14 야간수당 검증: 22시/06시의 포함·제외와 밀리초, 새벽~다음 새벽 24시간, 월·하루 시급 우선순위, 휴일과 야간의 가산 합산, 주휴 기준액 분리, 실제 휴게의 주간/야간 배분, 오래된 탭의 구간 보존, 휴게 미확인 정산 차단, 소급 정산본 보존, schema-3/4/5 복구를 격리 DB에서 검사한다. Node·Workerd 브라우저에서는 실제 휴게 구간 입력과 급여 표·내역·CSV를 확인한다. 대량 조회 테스트가 Cloudflare의 SQL 바인딩 100개 제한 초과를 발견해 배치를 100개로 제한했으며 같은 회귀 테스트를 유지한다. 운영 DB에는 테스트 근무를 추가하지 않는다.

조회 캐시 때문에 다른 관리자의 변경을 모든 화면에 즉시 푸시하지 않는다. 직원·기준·휴일은 최대 5분 재사용하며 필요하면 새로고침한다. 정산 확정 요청은 서버가 최신 자료와 지문을 다시 검사한다. 이 규모에 실시간 구독·추가 캐시 서버를 도입하지 않는다.

무료 한도에는 앱 외 계정 사용량·인증·요청 제한 등도 포함된다. 관리자 화면의 호출 수 감소는 총 서비스 비용의 일부이며, 실제 사용량은 Cloudflare에서 확인한다. 대규모 승인 대기 누적·수년 후 백업 크기 등 기존 확장 기준은 OPERATIONS.md에 남긴다. 테스트는 알려진 경계의 회귀 방지이며 모든 기기·장애 상황에서 무결점을 보증하지 않는다.
