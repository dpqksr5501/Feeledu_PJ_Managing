# 한국 공휴일 자동 반영

## 인증키 발급

1. [공공데이터포털의 한국천문연구원_특일 정보](https://www.data.go.kr/data/15012690/openapi.do)에 로그인한다.
2. **활용신청**에서 목적을 ‘학원 출퇴근·급여 시스템의 한국 공휴일 자동 반영’으로 작성한다. 신청 범위에 **공휴일 정보 조회**가 포함됐는지 확인한다.
3. 신청 승인 후 마이페이지의 **데이터활용 → Open API → 활용 중인 서비스**에서 해당 서비스를 연다. 화면 구성 변경 시 활용신청 현황에서 찾는다.
4. 일반 인증키 **Decoding** 값을 사용한다. 프로그램은 한 번 URL 인코딩된 Encoding 키도 처리하지만 Decoding 키가 권장된다. 승인 상태·활용기간·호출 한도도 확인한다.

키는 채팅·공개 저장소·릴리즈 설명·APK에 넣지 않는다.

## Cloudflare에 등록

1. [Cloudflare 대시보드](https://dash.cloudflare.com/) → **Workers & Pages** → **feeledu-attendance** → **Settings**.
2. **Variables and Secrets → Add**에서 유형 **Secret**을 선택한다.
3. 이름은 정확히 **KASI_SERVICE_KEY**, 값에는 발급받은 인증키를 입력한다.
4. **Deploy**로 적용한다. 기존의 다른 변수와 비밀 설정은 수정하지 않는다.
5. 관리자 웹 **설정 → 휴일·공휴일**에서 올해를 선택해 **공휴일 동기화**를 누르거나 최초 백그라운드 갱신을 기다린다. 처음에는 ‘초기 동기화 대기’, 실제 성공 후에 ‘자동 갱신 연결됨’으로 표시한다. 최초 상태 갱신은 화면에서 약 30초가 걸릴 수 있다.
6. ‘공식 자료 N일’과 최근 반영 시각, 해당 연도의 실제 공휴일 목록을 확인한다. 승인 직후 이용이 안 되면 포털에서 승인이 완료됐는지 확인하고 잠시 후 다시 시도한다. 같은 연도 수동 갱신 간격은 5분이다.

인증키 등록 전에는 ‘인증키 미등록’으로 표시하며 자동 연결이 완료됐다고 표시하지 않는다. 기존 수동 휴일과 이미 저장된 공식 자료는 유지한다. 키 값은 관리자 API·DB 백업에서도 반환하거나 저장하지 않는다.

로컬 Node 개발에서만 무시되는 `.env`의 `KASI_SERVICE_KEY`를 사용할 수 있다. 운영은 위 Cloudflare Secret을 사용한다. GitHub 자동 배포는 이 비밀값을 코드나 정적 빌드에 포함하지 않는다.

## 갱신 및 계산

- 고정된 HTTPS `getRestDeInfo` 주소에 연·월만 요청한다. 직원·급여·출퇴근 데이터는 전송하지 않는다.
- 12개월을 모두 검증한 뒤 한 트랜잭션으로 반영한다. JSON/XML, 월별 빈 목록·단일 항목·중복 명칭·페이지 누락을 처리한다. `isHoliday=Y`만 반영하며 기념일 전체를 휴일로 취급하지 않는다.
- 전년·올해·내년은 한국 시각 매일 **05:17**에 갱신한다. 최초 사용 시에도 백그라운드로 채우며, 사용 중에는 한 시간마다 갱신 필요 여부를 확인한다. 정상 갱신 후에는 23시간 동안 재호출하지 않는다. 실패한 연도는 한 시간 이후 재시도할 수 있다. 이전 연도는 설정에서 직접 선택한다.
- 대체·임시공휴일·선거일 등은 공식 응답의 날짜를 사용한다. 임의로 ‘다음 월요일’을 계산하지 않는다. 새로 지정된 날은 공급자가 자료에 반영한 뒤 다음 성공 갱신 때 적용된다. 급한 경우 공식 발표를 확인하고 수동 휴일로 추가한다.
- 공식 날짜에 새 휴일이 추가되면 자동 반영한다. 기존 날짜가 사라지면 전체 변경을 검토 대기 상태로 보존하며, 관리자에게 삭제·추가·명칭 변경 목록을 보여 준다. **변경 검토**에서 사유와 자료 버전을 확인한 뒤 적용한다. 공급자 오류가 기존 휴일을 자동 삭제하지 못하게 한다.
- 학원 수동 휴일은 별도 테이블을 사용한다. 같은 날짜가 공식·수동·정기 요일에 중복돼도 가산은 한 번이다. 공식·수동 날짜의 수동 항목을 지워도 공식 휴일은 유지한다.
- 특정일 시급이 있으면 그 시급을 단가로 사용한 후 휴일 배율을 한 번 적용한다. 한국 시간 자정을 기준으로 구간을 나누며 휴게시간 총분의 비례 배분 방식은 유지한다.
- 달력이 바뀌면 과거 예상 급여는 재계산한다. 확정 정산본은 수정하지 않으며 기존 급여 화면의 확정본·현재 계산 차액을 확인한다. 공휴일 반영·변경 승인·직접 확인은 변경 이력에 남긴다.

## 장애·확정 정산

- 인증 오류·타임아웃·429·비정상 HTTP 200·XML 오류·잘못된 날짜·부분 응답은 오류로 기록하고 이전 정상 목록을 유지한다. URL·인증키·원본 오류 본문은 기록하지 않는다. 응답 크기·동시 요청·시간·페이지 수를 제한한다.
- 연간 목록이 비었거나 지나치게 작거나 크면 반영하지 않는다. 최소한 8일, 1월 1일·12월 25일이 있어야 하며 최대 120일이다. 이는 한국 공휴일 산출 알고리즘이 아닌 부분 자료 탐지용 안전장치다. 이 조건에 영향을 주는 향후 제도 변경은 검증 기준도 업데이트한다.
- 출퇴근 요청은 외부 API 완료를 기다리지 않는다. 원격 API 장애와 관계없이 기록을 저장한다.
- 키가 연결됐거나 저장된 공식 달력이 있는 조회 기간은 달력 상태를 검사한다. 해당 연도 미확인·7일 경과·변경 검토 대기는 급여 경고로 표시하고 정산 확정을 막는다. 이미 확정한 정산은 유지한다.
- 장애 중 기존 목록이 정확하다고 공식 발표와 직접 대조했다면 **목록 확인 기록**에 사유를 남길 수 있다. 현재 자료의 지문이 일치해야 하며 7일 동안 유효하다. 검토 대기 변경은 먼저 처리해야 한다.
- 키를 삭제해도 저장된 공휴일을 없애지 않는다. schema-4 전체 백업에 공식 달력과 미승인 변경 상태를 포함한다. 비밀키는 복구 후 서버에 따로 등록한다. schema-3 백업은 달력이 없는 상태로 가져온다.

## 검증

정부 응답을 모사한 격리 테스트에서 월별 JSON/XML, 인증·부분·누락 실패, 인코딩 키, 중복 요청, 수동·공식 중복, 대체·임시 명칭, 날짜 경계, 소급 정산 보존, 검토 충돌, 7일 경과 확인, schema-3/4 백업 복구를 검증한다. Workerd SQLite에서도 XML 해석·저장을 실행한다. 테스트용 응답과 실제 인증키를 사용한 실서비스 연결 확인은 구분한다.

자료: [특일 정보 API](https://www.data.go.kr/data/15012690/openapi.do), [Cloudflare Secret 등록](https://developers.cloudflare.com/workers/configuration/secrets/).
